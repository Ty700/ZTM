When should I use either sorting method?

Quick and Merge are used most often because of the quicker Big of
    - Quick has a worst case of O(n^2) if we can't guarntee a pivot that isn't the "greatest" or "smallest" element

Use Cases of:
    Insertion Sort:
        Data is small or data is mostly sorted
            Pros:
            - Little space
            - Easy to implement

    Bubble Sort and Selection Sort:
        - Never
        - Educational 
        - Really bad
    
    Merge Sort:
        - Always guarntee a O(nlog(n))
        - Use if worried about worse case scenario
        - Worried about space complexity?
            - Might need to use quick sort or another sort
        - Not worried about space?
            - Use Merge
        
    Quick Sort:
        - One of the most popular sorts
        - Must pick a good pivot as the worst case, with a bad pivot, is O(n^2)
    
Can we beat O(nlog(n)) -> Mathmatically impossible for sorting
    - However, we can imporve on this by doing a non-comparison sort
        - What?
        - Entirely different way of sorting
        - Prior to, we compared by saying "Is this number greater than that number over there?"
        - Counting and Radix uses the way computers store numbers to sort
        - Only work with numbers, specifically numbers in a specific range
        - Other sorting methods can sort universally.
        - Bucket, Radix, and Counting can only do numbers of a specific length
